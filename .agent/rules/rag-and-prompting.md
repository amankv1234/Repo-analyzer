# Rule: RAG Architecture & Prompting Guidelines

## Scope
Applies to `packages/core/src/rag`, `packages/core/src/llm`, and `packages/prompts/`.

---

## 1. Chunking Philosophy

- **AST-Aware Semantic Boundaries**: Never chunk code using naive sliding windows of arbitrary character or word counts. Naive splitting cuts functions in half and ruins call-graph comprehension.
- **Tree-Sitter Grammar Units**:
  - Functions, methods, classes, interfaces, struct definitions, enum declarations, and standalone module exports form atomic chunks.
  - Chunks retain symbol metadata: `symbol_name` (e.g., `calculateRRFScore`), `symbol_type` (e.g., `function_declaration`), `start_line`, `end_line`.
- **Chunk Size Limits**:
  - Target chunk size: 300 - 800 tokens.
  - Large functions (>1,500 tokens) are split hierarchically along internal control structures (e.g., major `switch` or `try/catch` blocks) with parent symbol context preserved in metadata.

---

## 2. Hybrid Retrieval & RRF Merge

- Real codebase queries require both **exact keyword matching** (variable names, error codes, config keys) and **semantic similarity** (e.g., "where is user authentication handled?").
- Dual-Retriever Strategy:
  1. **Dense Vector Search**: pgvector HNSW cosine distance (`embedding <=> query_vector`).
  2. **Sparse Lexical Search**: PostgreSQL Full-Text Search with `to_tsvector('english', content)` and `ts_rank_cd`.
- **Reciprocal Rank Fusion (RRF)** combines ranks without score calibration problems:
  $$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
  Default smoothing constant $k = 60$.

---

## 3. Strict Citation & Grounding Rules

- Every claim or code explanation generated by the assistant must cite exact source references:
  `[path/to/file.ext:start_line-end_line]`.
- System instructions enforce an explicit fallback policy:
  > "If the provided code chunks do not contain sufficient evidence to answer the user's question, you must explicitly state that the answer was not found in the indexed repository code. NEVER invent functions, configuration options, or architectural patterns."

---

## 4. Prompt Governance

- **No Inline Prompts**: Prompts must never be embedded directly inside service logic.
- All prompts reside in `packages/prompts/src/v<number>/<prompt-name>.prompt.ts`.
- Each prompt export must include:
  - `id`: Unique identifier (e.g., `repo_overview_generation`).
  - `version`: Semantic version string (`1.0.0`).
  - `description`: Purpose and intended model family.
  - `inputSchema`: Zod schema validating variables required to hydrate the template.
  - `render()`: Deterministic hydration function returning formatted prompt text.
